Abstract

Inside a portfolio of FlyRank client pages, can a page's age, freshness, and search position — not its topic or backlinks — separate pages gaining visibility from pages losing it?

Using two non-overlapping months of the FlyRank ML Internship warehouse (feature month vs. label month), a transparent reason-code rule set and a logistic regression were each evaluated against a majority-class baseline on the same held-out split. The model matched but did not beat the baseline (62.2% accuracy for both, ntest = 16,629), and never predicted the minority "growing" class at the default threshold — a negative result reported honestly rather than reframed.

The stronger, more useful finding was structural: click-through rate fell roughly 73% from top-3 to deep search positions in this sample, which is what powers the ranked, reason-coded action queue this paper recommends for editorial review.

1

Introduction

With a few thousand pages and a small editorial team, the real question isn't "will our rankings change" — it's which pages get reviewed first this week. This paper's output is a ranked, reason-coded queue for a human editor to work through, not an automated publishing action.

Simple, auditable group differences were tried first; a held-out model was added second, used only to check whether that simple story survives a proper train/test split — not because a fancier model was assumed to be better on its own merits.

Excluded, and why

  • Product-computed fields (e.g. a health score) — not shipped in this warehouse release at all, so there was nothing to exclude.
  • "Not indexed" style fields — don't exist in the real schema; recommendations depending on them were dropped rather than fabricated.
  • Revenue — not tracked in this dataset; clicks × CPC is used as a value proxy instead, never presented as a revenue figure.
  • content_updated_date as a decision-time-safe signal — dim_content is a single frozen snapshot, so freshness-based reason codes are kept but treated as directional-only.
Public-safe: no brand names, URLs, page titles, or query strings appear anywhere in this paper — every number is a computed aggregate.
3

Methodology

Label. A page is labeled growing if label-month impressions rose more than 10% above the feature month, and declining if they fell more than 10%; pages in between ("stable") are excluded from this classification task.

Features. content_age_days, days_since_update, avg_position, word_count, intent, competition. Feature-month impressions and clicks were deliberately left out — since the label is derived from a change starting at that same value, including them would let the model partly reconstruct its own answer.

Baseline. A majority-class predictor. Its accuracy is exactly the base rate, and it's reported in the same table as the model — not a token comparison buried in prose.

Validation design. A single stratified 80/20 train/test split (seed 42), so the baseline and the model are scored on identical held-out rows. This is a random row-level split, not grouped by client — flagged explicitly below, since a prior audit on this same project found random splits can overstate performance versus a client-grouped split.

Leakage checks passed: no product-computed field in the feature matrix, feature-month impressions/clicks excluded, no page identifier used as a feature, stratified split confirmed to preserve the base rate in both folds, and all numeric features scaled using training-fold statistics only.

Limitations & honest framing

  • Observational

    No page was randomly assigned to be refreshed or left alone, so any refresh-vs-stale comparison elsewhere in this project likely carries selection bias.

  • Random split

    A prior audit measured a meaningful ROC-AUC gap between a random split and a client-grouped split. Section 4's result should be read as an upper bound, not a final number.

  • Coarse label

    Collapsing a continuous impressions change into growing/declining and dropping "stable" pages means reported accuracy describes only the directional-extremes subset.

  • No inference

    No confidence interval or significance test accompanies the metrics above — treat the baseline/model gap as directional, not certified.

  • Freshness signal

    dim_content is a frozen snapshot rather than a per-month history, so age- and update-based fields aren't reliably decision-time-safe.

  • No revenue

    This analysis doesn't touch AI-session data, and this dataset has no booked-revenue field — any value estimate uses clicks × CPC, never revenue.

Ranked recommendations

Even though the classifier didn't beat the baseline, this queue still works as decision support — it's built from real, recomputed CTR and position benchmarks, not from the unproven model.

  • 1

    Refresh pages with no update in 180+ days DECAY_RISK

    140 pages flagged. Directional only — content_updated_date is a frozen snapshot, not decision-time-safe.

  • 2

    Fix titles/snippets on already-ranking page-1 pages PAGE1_CTR_GAP

    65,690 pages flagged. ~73% CTR drop from top-3 to deep positions makes this the cheapest lever available — better metadata, not net-new content.

  • 3

    Strengthen relevance / internal links on striking-distance pages STRIKING_DISTANCE

    25,883 pages flagged. Positions 11–20 sit in the steepest CTR step-up zone in this sample's own position-tier table.

  • 4

    Expand thin pages that already earn impressions THIN_BUT_VISIBLE

    6,335 pages flagged. Word count is not a strong signal overall, but growing pages average more words than declining pages in this sample.

  • 5

    Prioritize low-competition commercial/transactional topics LOW_COMP_COMMERCIAL

    Lowest-competition commercial/transactional pages in this sample, ranked by keyword competition score.
